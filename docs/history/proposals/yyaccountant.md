# yyaccountant 初期方針（2026-10-29）

## 要求

- YYprojectの実装を参考に、YYaccountantを追加する。
- 支出と収入、債権と債務、予算と計画、複数の原材料や設備を使う製品の原価管理、各種統計に基づく今後の支出予想を管理する。
- 数値計算はすべて十進数で行う。
- 勘定科目の選択に迷わないように、似たものには詳細な使い分けの説明を付ける。
- 個人の家計の支出から個人事業主の財務管理までをスコープにする。
- データは単一のSQLiteファイルで管理する。

## 判断

| 論点 | 採用 | 理由 |
|---|---|---|
| 記帳方式 | 複式簿記に統一し、家計向けに「支出・収入・振替」のかんたん入力を用意 | 家計と事業で同じ帳票・検証を使え、カード払い・ローン・按分を正しく表せる |
| 数値 | `rust_decimal`、JSONは文字列、SQLiteはTEXT | 浮動小数点の誤差を入力・計算・保存のどこにも入れない |
| 保存 | 1ファイルに複数帳簿。コレクションごとの関係テーブル | YYprojectの「1案件=1 JSON文書」より、仕訳が増えても外部からSQLで参照しやすい。版・監査の仕組みはYYprojectと同じ |
| 科目の説明 | 科目ごとの説明・検索語と、似た科目の比較（例つき）をコードに持ち、文書を生成 | 画面・MCP・文書の説明を一致させる |
| 予測 | 複数の統計手法をバックテストで選び、計画・返済予定を加算 | 定期支出と変動支出を分け、二重計上を避ける |
| UI | YYprojectと同じ認証方式のWeb UIとstdio MCP | Linux／Windowsの両方で同じ操作ができる。WindowsネイティブGUIは後続の検討とする |
| 削除 | 仕訳は取消（void）で残す。マスタは未使用のときだけ削除 | 監査と帳簿の連続性 |

## 後続の候補

- 決算整理（棚卸・前払/未払の振替、元入金の繰越）の支援
- 消費税の区分と集計
